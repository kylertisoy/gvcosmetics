# GV Cosmetics — Backend + API-Connected Frontend

This adds a real Python backend to the GV Cosmetics shop/admin site. The frontend
no longer uses hardcoded JS arrays — it talks to a FastAPI + PostgreSQL API for
products, accounts, orders, wishlists, ratings, addresses, notifications, and
admin analytics.

## What's included

```
backend/                  FastAPI + PostgreSQL API
  app/
    main.py               App entrypoint (CORS, routers, table creation)
    database.py           SQLAlchemy engine/session
    models.py              Users, Products, Orders, OrderItems, Addresses,
                           Wishlist, Ratings, Notifications
    schemas.py             Pydantic request/response models
    auth.py                Password hashing + JWT auth
    seed.py                 Seeds the DB with the original 29 products +
                           the demo customer/admin accounts
    routers/
      auth.py              /auth/register, /auth/login, /auth/me, change-password
      products.py          /products (CRUD + ratings)
      orders.py            /orders (checkout, listing, admin status updates)
      addresses.py         /addresses
      wishlist.py          /wishlist
      notifications.py     /notifications
      customers.py         /customers (admin)
      analytics.py         /analytics (admin dashboard + reports)
  requirements.txt
  .env.example

frontend/
  gvci_updated.html        Same UI, now wired to call the API instead of
                           using hardcoded data
```

## 1. Set up the database

You need PostgreSQL running locally (or point `DATABASE_URL` at any Postgres
instance you have — a managed one works too).

```bash
# Ubuntu/Debian example
sudo apt-get install postgresql
sudo service postgresql start
sudo -u postgres psql -c "CREATE USER gvci WITH PASSWORD 'gvci_pass' CREATEDB;"
sudo -u postgres psql -c "CREATE DATABASE gvci_db OWNER gvci;"
```

## 2. Set up the backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # adjust DATABASE_URL / SECRET_KEY if needed

python -m app.seed              # creates tables + seeds products & demo accounts
uvicorn app.main:app --reload --port 8000
```

The API is now at `http://localhost:8000`. Interactive docs (auto-generated by
FastAPI) are at `http://localhost:8000/docs`.

Demo accounts seeded by `app.seed`:
- Customer: `customer@gv.com` / `1234`
- Admin: `admin@gv.com` / `admin123`

## 3. Run the frontend

The frontend is a static HTML file — just open it in a browser or serve it:

```bash
cd frontend
python3 -m http.server 8080
```

Then visit `http://localhost:8080/gvci_updated.html`.

By default the page calls the API at `http://localhost:8000`. To point it
somewhere else (e.g. a deployed API), set this before the page's scripts run,
or just edit the `API_BASE` constant near the top of the `<script>` block:

```html
<script>window.GVCI_API_BASE = 'https://your-api.example.com';</script>
```

## How data flows now

- **Login** calls `POST /auth/login`, stores a JWT in `localStorage`, and is
  automatically restored on page refresh via `GET /auth/me`.
- **Products** are fetched from `GET /products` (with ratings aggregated
  server-side) on login and after any admin edit.
- **Checkout** calls `POST /orders`, which decrements stock, awards loyalty
  points, and creates a notification — all in the database.
- **Wishlist, ratings, addresses, notifications** are all persisted per user
  via their respective endpoints, instead of living only in page memory.
- **Admin** dashboard/analytics/customers/orders/inventory panels pull from
  `/analytics`, `/customers`, `/orders`, and `/products` so multiple admins
  (or a refreshed page) see the same live data.

## Notes / things you may want to extend

- Payment is still just a UI dropdown (COD/GCash/etc.) — no real payment
  gateway is wired up.
- Product images are still emoji placeholders; there's no file upload yet.
- "Save Profile" (display name) is currently local-only — add a
  `PATCH /auth/me` endpoint if you want it to persist.
- CORS is wide open (`CORS_ORIGINS=*`) for local development — lock this down
  to your actual frontend origin before deploying.
- The JWT secret in `.env.example` is a placeholder — generate a real random
  string for `SECRET_KEY` before deploying anywhere public.
